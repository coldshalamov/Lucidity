## Attack questions

1. Does the three-package root-sibling topology preserve upstreamability without collapsing host/catalog/UI/backend responsibilities into an unreviewable monolith?
2. Is extracting `wezterm-gui` into a library plus thin stock binary feasible at the claimed paths, or does initialization/global state/resource ownership require a different seam?
3. Reconstruct actual window → `TermWindow` → layout/render/input/mux ownership. Identify any geometry consumer omitted from the proposed `AppLayout` contract.
4. Can terminal content escape a bounded viewport in either renderer through backgrounds, images, glyph effects, decorations, overlays, scrollbars, or splits? State what real acceptance evidence is required.
5. Reconstruct current Windows close behavior. What must distinguish UI close, pane stop, app Quit, UI crash, and host crash without orphaning or killing the wrong process?
6. Attack `OrganizationState`/`RuntimeState`, attachment generations, `/new` rebinding, event/file races, crash reconciliation, and duplicate delivery.
7. Attack the named-pipe JSON candidate for same-user security, framing, backpressure, versioning, reconnect, and extension feasibility.
8. Identify overlapping Wave 1 write scopes, especially shared Cargo files, `agent-terminal`, `frontend.rs`, native window code, and protocol types.
9. Attack accessibility, focus traversal, IME, keyboard ownership, settings forms, and whether the proposed renderer strategy can deliver a sleek native product without a second web runtime.
10. Identify tests that would pass while the player-visible behavior is still wrong.
