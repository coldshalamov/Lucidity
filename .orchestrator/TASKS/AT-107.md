## Objective

Implement ADR-003's opt-in `OwnedJob` PTY spawn policy so Agent Stop, Quit, and hard-host-crash semantics own the full Windows process tree while stock launches remain byte-for-behavior stock.

## Exclusive write lease

- `pty/src/cmdbuilder.rs` or the smallest existing command-policy surface
- `pty/src/win/mod.rs`
- `pty/src/win/psuedocon.rs`
- narrowly required Windows PTY helpers and focused tests

No mux/GUI/window/product-host/Cargo-workspace edits. A required dependency or broader API change is a controller proposal, not an inline expansion.

AT-099 pre-enables the existing WinAPI `jobapi2` feature in `pty/Cargo.toml`; this worker must verify that declaration at its base and must not edit the manifest.

## Requirements

1. `DirectChild` is the default and preserves current `CreateProcessW` flags and direct kill behavior.
2. `OwnedJob` creates/configures a Job Object with kill-on-last-handle-close, creates the root process suspended, assigns it, and resumes only after success.
3. Child and cloned killer retain appropriate job handles; their explicit kill terminates the job tree.
4. Failure at any stage cleans up the suspended process/handles and returns an actionable error; never silently downgrade to direct-child ownership.
5. Cover nested-job/access-denied, breakaway attempts, clone/drop order, natural exit, explicit terminate, and host-process-death behavior with native Windows receipts.
6. No Agent launch may rely on PID enumeration as the termination mechanism.

## Acceptance

Run focused PTY tests, `cargo test -p portable-pty` (or the live package name), dependent mux checks, and a native helper parent→child→grandchild matrix. Prove stock and Agent policies separately and inspect zero leaked handles/processes.

## Stop and escalate

ConPTY cannot combine suspended creation with the required process-thread attributes, the current host job forbids assignment, a breakaway policy weakens guarantees, or stock creation flags would change.
