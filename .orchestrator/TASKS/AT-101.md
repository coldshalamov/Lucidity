## Frozen contracts

- Stock mode reproduces current geometry and behavior.
- Agent mode uses one `AppLayout` result for every geometry/input consumer.
- Chrome hit regions never become terminal input.
- Half-open layout rects adapt to inclusive `UIItem` bounds with checked `width - 1`/`height - 1`; chrome backgrounds are full-bleed and deliberate hit gaps are forbidden.
- The accepted design has no general accent, no forced terminal palette, no scheduled chrome animation, and only conflict-aware/remappable default global chords `Ctrl+Shift+A/B`.
- Built-in tab bar remains until sidebar tab activation is proven.
- No change to conversation/runtime semantics.

## Implementation sequence

1. Create the smallest auto-discovered `src/lib.rs` seam and keep the stock `wezterm-gui` binary thin without editing its manifest.
2. In a separate commit after the library target exists, add the existing `wezterm-gui` path dependency to `agent-terminal/Cargo.toml` and verify the exact mechanical lock delta; reject Cargo's missing-library warning and any unrelated manifest change.
3. Prove stock build/tests before Agent behavior.
4. Start `agent-terminal` through the same accepted bootstrap with Agent mode disabled.
5. Add pure layout calculation and boundary/DPI/tiny-window tests.
6. Thread layout through initial dimensions, resize/PTY dimensions, Windows resize increments, render bounds/origin, mouse/cell mapping, selection, hyperlinks, scrollbar, cursor/IME, drag/drop, overlays, Win11 maximize-button/non-client geometry, snap-layout hover, and hit testing.
7. Render the fixed header/sidebar skeleton in Agent mode only, with full-bleed typed hit coverage and explicit terminal containment in both rendering backends. Follow the accepted contract's 32-pixel title bar, responsive 200/264/320/hidden sidebar, State Rail, Weld, and adaptive seam; do not widen this slice into the full catalog UI.
8. Add two typed sidebar actions carrying stable `TabId`; resolve the current index only at dispatch time through the existing mux activation path.
9. Implement the smallest accepted chrome-focus entry/exit and prove modal/key/IME precedence without stealing stock or TUI input. User-explicit keybindings win over default product chords.
10. Prove title drag, double-click maximize, maximize-button Win11 snap geometry, hover without chrome-tree rebuild, and no Lucidity animation scheduling.
11. Suppress the stock tab bar in Agent mode only after switching and real OS input are green.

## Non-functional requirements

- Native Windows and performant Rust; no second UI/runtime stack.
- No fixed polling or continuous invalidation.
- No unsafe code without a localized, justified invariant.
- Preserve stock behavior when Agent mode is off.
- Keep commits small enough to review library extraction separately from geometry and chrome.

## Stop and escalate

- A public frozen contract or shared Cargo file must change.
- Terminal containment requires a renderer-wide API outside the write set.
- Agent mode cannot preserve stock initialization/resources.
- Native lifecycle/tray ownership becomes necessary.
- Sidebar activation requires changing the coupled CLI path in `wezterm/src/main.rs` or changes stock activation semantics.
- Required DPI/IME/image evidence is unavailable.
