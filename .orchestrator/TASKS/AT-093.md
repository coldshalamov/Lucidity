# AT-093 — Opus Native Visual-System Pass

OWNER: Claude Code / Claude Opus 5, Extra High (`xhigh`)
MODE: read-only design pass, fresh session
BASE: accepted Wave 0 control plane
WRITE SET: none; controller persists accepted artifact

## Objective

Create one bold, coherent, implementation-aware native visual and interaction system for Lucidity's protected desktop corridor. It must look designed rather than like stock WezTerm with a generic SaaS sidebar, while remaining fast, dense, legible, accessible, and feasible on the accepted renderer seam.

## Read

- `.orchestrator/{CHARTER,SOURCE_CONTEXT,INTERFACES,RISKS,VERIFICATION}.md`
- `.orchestrator/ADRS/ADR-001-accessibility-demo-scope.md`, ADR-002, and ADR-003
- accepted AT-080/090/091/092 findings
- exact WezTerm box-model/tab-bar/font/icon sources relevant to feasibility
- HACKATHON demo and sidebar requirements

Treat the accepted architecture as fixed: one native process for the protected demo, stable `TabId` actions, no background updater/network polling, true close-to-tray semantics, and a bounded terminal viewport. Do not spend the design pass re-litigating transport, Job Objects, or package topology.

## Deliverable

A native UI specification containing:

1. a one-sentence aesthetic north star and what makes the product memorable;
2. information hierarchy for window chrome, active work, settled history, terminal, status, usage, and settings;
3. logical-pixel dimensions, spacing rhythm, density rules, responsive/minimum-window behavior, and DPI rules;
4. typography using redistributable/bundled/system-safe assets with fallbacks;
5. named color/elevation/border/focus tokens for light/dark or one justified MVP theme;
6. exact row anatomy and every runtime/organization/attention state;
7. icons and agent-identity treatment without copying vendor trademarks improperly;
8. hover/pressed/focus/disabled/loading/error/empty/offline/stale states;
9. keyboard and focus order, stable semantic names/view-model IDs for future UIA, contrast targets, reduced-motion behavior, IME/modal priority, and raw-TUI shortcut mode; do not claim a current Windows screen-reader provider;
10. usage/context dropdown and minimal settings-shell interaction;
11. motion/invalidation rules that preserve idle CPU and avoid decorative redraw churn;
12. fixed-size acceptance frames at 100%, 125%, 150%, and 200% DPI;
13. component/state inventory suitable for deterministic screenshot fixtures;
14. explicit cuts for the hackathon corridor.

## Constraints

Native Rust/WezTerm renderer constraints are real. No HTML/CSS/React implementation, Electron, Tauri, WebView, generic purple-gradient aesthetic, gratuitous transparency, or layout that depends on continuous animation. Do not redesign lifecycle/product scope.

## Return

The full design specification, implementation-risk notes, unresolved decisions, and exact source files inspected. No code edits.
